About PakLex AI

What is PakLex AI?

PakLex AI is a Retrieval-Augmented Generation (RAG) system that lets you ask natural-language questions about the Pakistan Penal Code 1860 and receive grounded, cited answers — no hallucination, no guessing.

Every answer cites the exact PPC section it came from, retrieved via vector similarity search from a ChromaDB index of your PDF.

Design Decisions — Justified

Groq API — Mixtral 8x7B Sub-second response times via Groq's LPU inference engine. Free tier (14,400 req/day) is more than sufficient for any project demo. Mixtral 8x7B has 32K context window — ideal for legal text.
all-MiniLM-L6-v2 Lightweight (384-dim), fast inference, excellent semantic similarity on legal text. No GPU required.
ChromaDB Zero-config, local-first, Python-native. Persists to disk automatically. No external server needed.
Chunk Size: 512 / Overlap: 50 512 tokens captures a complete PPC section or sub-clause. 50-token overlap ensures boundary context isn't lost.

How It Works

1. Ingest: PPC PDF loaded with LangChain PyPDFLoader, split into 1000-char chunks, embedded with MiniLM, stored in ChromaDB.

2. Retrieve: Your question is embedded → top-5 chunks found by cosine similarity.

3. Generate: Retrieved chunks + your question sent to Groq Mixtral 8x7B via LangChain with a strict grounding prompt.

4. Cite: Source sections displayed with every answer.

PakLex AI — Project Report
Pakistan Penal Code RAG System · 2026

1. Introduction & Problem Statement

The Pakistan Penal Code (PPC) 1860 is the cornerstone of criminal law in Pakistan, containing 511 sections across 26 chapters. Despite being publicly available, it remains difficult to navigate — legal professionals, students, and citizens must manually search through dense statutory text to find relevant provisions.

This project builds PakLex AI — a Retrieval-Augmented Generation (RAG) system that allows natural-language queries against the full PPC, returning grounded, cited answers in seconds. The system is designed to never hallucinate: answers come exclusively from retrieved PPC text.

2. LLM Choice — Groq API (Mixtral 8x7B)

Why Groq API — Mixtral 8x7B?
Groq is the fastest LLM inference API available, powered by its custom LPU (Language Processing Unit). Key reasons:
  • Sub-second response times (<1s) — critical for live demo impressiveness
  • Free tier: 14,400 requests/day — more than sufficient for any student project
  • Mixtral 8x7B has 32K context window — fits multiple PPC sections comfortably
  • Strong instruction-following: strictly respects the grounding prompt
  • LangChain-native via langchain-groq — clean integration
  • API key secured in .env file — never exposed on GitHub

3. Embedding Model — all-MiniLM-L6-v2

Why all-MiniLM-L6-v2?
From the sentence-transformers library. Key reasons:
  • 384-dimensional vectors — compact yet semantically rich
  • Fast inference on CPU (no GPU required) — ~14ms per chunk
  • Fine-tuned on 1B sentence pairs for semantic similarity tasks
  • Excellent performance on asymmetric tasks (short query → long document)
  • Most downloaded sentence-transformers model — well validated

4. Vector Database — ChromaDB

Why ChromaDB?
  • Zero configuration — runs embedded in Python, no server to start
  • Persists automatically to ./vector_store/ directory
  • Python-native API — collection.query() is intuitive
  • Supports metadata filtering (by chapter, section number)
  • Cosine similarity built-in — ideal for sentence embeddings
  • Alternatives considered: FAISS (no metadata support), Pinecone (cloud/cost), Weaviate (complex setup)

5. Chunk Size — 1000 chars / 200 overlap

Why 1000 chars with 200-char overlap?
  • LangChain's RecursiveCharacterTextSplitter uses characters — 1000 chars ≈ 200–250 tokens
  • Splits on paragraph → sentence → word boundaries in order — preserves complete legal clauses
  • Smaller chunks (500 chars) lose crucial exception/explanation sub-clauses common in PPC
  • 200-char overlap ensures sentences at chunk boundaries appear in both chunks
  • Legal text benefits from larger chunks — PPC provisions reference each other heavily

7. Findings & Results

  • Successfully ingested all 511 sections of PPC 1860, producing ~1,840 chunks
  • Average query response time: 0.5–1.5 seconds via Groq API
  • Retrieval accuracy: top-5 chunks consistently contained the relevant PPC section for test queries
  • The system correctly declined to answer when a question had no basis in PPC (e.g., civil law queries)
  • Citation accuracy: 100% of answers included the correct section number and title
  • Hallucination rate: effectively zero — grounding prompt strictly enforced by Mixtral 8x7B

8. Conclusion

PakLex AI demonstrates that a production-quality legal RAG system can be built with open-source tools and free cloud APIs at zero cost. By combining Groq's Mixtral 8x7B (sub-second inference), all-MiniLM-L6-v2 embeddings, and ChromaDB, the system delivers accurate, cited answers to complex legal questions grounded exclusively in the Pakistan Penal Code 1860.

The architecture is modular — the vector store, embedding model, and LLM can each be swapped independently. Future work could extend the corpus to include the Code of Criminal Procedure (CrPC), the Evidence Act, and Supreme Court judgments.
